# Feature: Upstream Sync Rehearsal

## Overview
A reusable rehearsal track to validate and execute the upstream synchronization workflow for the DPS fork (`sbs-ru` branch). This process ensures that the fork stays up-to-date with the main DPD repository while preserving all DPS-specific customizations (Russian localization, SBS data, unique GUI views, and specialized logic).

## Goals
1.  **Tooling Validation:** Confirm that `scripts/bash/full_sync.sh` correctly utilizes the `dps_sync_registry.json` for exclusions.
2.  **Synchronize Branches:** Execute a selective pull from `as_upstream` to `sbs-ru`, ensuring that modified upstream files are correctly restored to their local state.
3.  **Manual Logic Integration (Major Files):** Review changes in `modified_upstream_files` and port relevant upstream bug fixes or features to the localized versions in `sbs-ru`.
4.  **Shadow Copy Porting (Localized Files):** Systematically compare all shadow copies (`russian_copies` and `sbs_copies` in registry) with their upstream sources. Port functional logic updates while strictly preserving `RuPaths`, `DPSPaths`, and translation/SBS specialized logic.
5.  **Documentation Parity:** Ensure all new English documentation has corresponding entries in the Russian documentation folder.
6.  **Verify Integrity:** Validate that the system remains functional after synchronization (e.g., UI loads correctly).

## Model Usage Guidelines
To ensure high-quality reasoning and prevent regressions, the AI agent MUST adhere to the following model strategy. Models can be switch only my user manually after reminder:
- **FLASH Model:** Use for initial automated sync, listing files, simple diffing, documentation placeholder creation, and running existing tests.
- **PRO Model:** REQUIRED for the "Manual Logic Integration" and "Systematic Shadow Update" tasks. Porting logic requires deep semantic understanding of why upstream changed and how it impacts localized features.
- **PRO Model:** REQUIRED for "Expand Test Suite" to identify subtle edge cases introduced by upstream updates.

## 🛑 Unambiguous Approval Protocol
The agent MUST NOT commit or advance phases based on error feedback. **Explicit approval** (e.g., *"Phase X is complete"*) is required before every commit or phase transition.
- **HARD STOP:** The agent MUST pause and wait for this exact string before executing any final commit or moving to the next phase.

## Key Artifacts
-   **Registry:** `conductor/templates/upstream_sync_rehearsal/dps_sync_registry.json` (The source of truth for sync logic).
-   **Guide:** `conductor/templates/upstream_sync_rehearsal/guide.md` (Detailed preservation and merge guidelines).
-   **Script:** `scripts/bash/full_sync.sh` (The primary execution tool).

## Success Criteria
-   `dpd-sync-folders` completes without errors.
-   `sbs-ru` is updated with `as_upstream` content (excluding registered paths).
-   Manual merges for all files in `modified_upstream_files` are performed according to the Guide.
-   **Systematic Shadow Update:** All changes in latest commits generated by `scripts/bash/full_sync.sh` are implemented in their corresponding shadow localized copies (if the file is mentioned as a source in `russian_copies` or `sbs_copies`).
-   Verification tests (`tests/test_dps_imports.py`, `tests/test_dps_logic.py`, `tests/test_dps_exporters_functional.py`, `tests/test_dps_docs_parity.py`) pass, confirming module integrity and logic preservation.
-   The application builds and runs correctly, with DPS views intact.
-   All changes are committed with a timestamped message.
