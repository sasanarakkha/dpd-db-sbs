### Sync Improvement Proposal

#### 1. Missing Workflow Rules vs. Agent Mistakes
**Missing Workflow Rules (Systemic gaps to fix):**
* **[CE-1 Scope Overreach]**: The workflow lacks a mechanism for handling conceptual scopes (like "last 5 commits"). **Rule to add:** "Always resolve conceptual filters to a concrete file list (via `git diff`) before evaluating them against registry rules."
* **[CE-2 Exclusion Leak]**: Upstream added new files in `conductor/` and `kamma/` (which are in `no_sync_files`). `execute_sync.py` uses `git restore --source as_upstream --worktree -- .` to pull upstream changes, making those new files UNTRACKED in the worktree. It then tries to exclude them by restoring the original state with `git restore --source sbs_ru_original_sha --staged --worktree -- conductor/`. Because `git restore` ignores untracked files, the new upstream files remained in the worktree. Later, `git add .` staged them, sneaking them into the sync commit. **Fix:** Update `execute_sync.py` to clean untracked upstream additions in excluded paths (e.g. `git clean -f -d -- <path>`).
* **[E-2 Stale Whitelist]**: The testing framework lacks a validation check to ensure whitelist entries in `test_shadow_parity.py` accurately match the Fully Qualified (FQ) paths generated by the AST extractor. 
* **[E-4 Coupled Templates]**: The Phase 2 planning process does not mandate checking `registry.json` for associated `.jinja` templates when a Python shadow file is modified.
* **[E-3 Type Narrowing]**: **Rule to add:** "Verify union types across all parallel localized classes (e.g. `RootsData_dps`) when upstream type definitions change."

**One-off Agent Mistakes (Execution failures):**
* **[E-1 Stale Handoff]**: The agent committed Batch 1 but failed to update the handoff's "Next Action" before writing the restart prompt.
* **[F-1 Parallel Edit]**: The agent attempted to use the replace tool on files it hadn't read yet.
* **[F-4 Stale Ledger]**: The agent resolved an approval gate but forgot to mark the TODO as DONE.

#### 2. Friction Points for `guide.md` & Templates
* **Implicit Dependency Imports [F-2]**: Add a note: *"SBS/Russian shadow exporters may need to explicitly import missing upstream utilities (e.g., from `tools.utils`) if they are not re-exported in localized utility files."*
* **Regex Precision [F-3]**: Add a note: *"When verifying function calls via grep, use word boundaries (`\bopen\(`) or exclude methods (`[^.]open\(`) to prevent false positives (like `Path.open()`)."*
* **Whitelist Management [F-5]**: Add a note: *"If an import is intentionally dropped in a shadow copy but retained upstream, it must be added to the `test_shadow_parity.py` whitelist."*

#### 3. Stages 4 and 5 Redesign
*Given they are consistently skipped, they should be decoupled from the core sync to reduce fatigue.*
* **Stage 4 (Docs Parity):** Move documentation syncs to an asynchronous "Docs Backlog" file (`kamma/upstream_sync/docs_translation_queue.md`). Stage 3 simply appends changed docs to this queue, allowing the sync to finish without blocking on translation work.
* **Stage 5 (Retrospective):** Replace the heavy `new_improvements.md` process. Instead, use an inline "Errors & Friction Log" added directly to the `handoff.md` during execution (as successfully done in this session). The final step of Stage 3 becomes a mandatory, short (10-min) ADVANCED model review that reads the log and directly applies updates to `archive_improvements.md` and `guide.md`.

#### 4. Additions to `archive_improvements.md`
* **Execute_sync.py Untracked Exclusions Flaw:** Document the failure mode of using `git restore` on untracked files within excluded directories to prevent similar issues in future script automation.
* **Context Compaction Resilience:** Document that the workflow's resilience to context limits depends entirely on the durably written `handoff.md` and `dynamic_plan.md`. The handoff must always reflect the *exact* state before any session boundary.
